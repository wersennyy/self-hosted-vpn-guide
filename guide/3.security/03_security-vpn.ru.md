## Безопасность сервера (VPS)

Этот раздел посвящён защите вашего VPS. Я настоятельно рекомендую пройти эти шаги **до** или **сразу после** установки панели, чтобы не подвергать сервер лишнему риску.

Безопасность — это не одна команда, а набор мер. Мы разберём всё по порядку: от SSH-ключей до фаервола и защиты от брутфорса.

---

### 1. SSH-ключи и отключение входа по паролю

Самая первая и важная мера — перейти на вход по SSH-ключам и отключить вход по паролю.

#### Что такое SSH-ключи

SSH-ключи — это пара файлов:

- **Приватный ключ** — хранится у вас на компьютере, его нельзя никому передавать.
- **Публичный ключ** — копируется на сервер и используется для проверки вашей личности.

Вместо пароля вы используете ключ. Это надёжнее и удобнее.

#### Генерация SSH-ключей (на вашем компьютере)

**На macOS / Linux:**

1. Откройте терминал.
2. Выполните команду:

   ```bash
   ssh-keygen -t ed25519 -C "your_email@example.com"
   ```

3. Нажмите Enter, чтобы сохранить ключ в расположении по умолчанию (`~/.ssh/id_ed25519`).
4. Придумайте и введите парольную фразу (passphrase) — это дополнительная защита ключа. Можно оставить пустым, но я рекомендую задать.

**На Windows (через PuTTY):**

1. Скачайте и запустите [PuTTYgen](https://www.puttygen.org/).
2. Выберите тип ключа **Ed25519** (или RSA 4096, если Ed25519 недоступен).
3. Нажмите **Generate** и поводите мышкой, чтобы создать случайность.
4. Сохраните приватный ключ (кнопка **Save private key**) в надёжное место.
5. Скопируйте публичный ключ из верхнего поля.

#### Копирование публичного ключа на сервер

**На macOS / Linux:**

1. Выполните команду (замените `root@IP_АДРЕС` на ваши данные):

   ```bash
   ssh-copy-id root@IP_АДРЕС
   ```

2. Введите пароль от сервера, когда попросят.

**На Windows (через PuTTY):**

1. Подключитесь к серверу по SSH через PuTTY (по паролю).
2. Создайте папку для ключей:

   ```bash
   mkdir -p ~/.ssh
   chmod 700 ~/.ssh
   ```

3. Откройте файл `authorized_keys`:

   ```bash
   nano ~/.ssh/authorized_keys
   ```

4. Вставьте публичный ключ (одной строкой, без переносов).
5. Сохраните (`Ctrl+O`, `Enter`) и выйдите (`Ctrl+X`).
6. Установите правильные права:

   ```bash
   chmod 600 ~/.ssh/authorized_keys
   ```

#### Проверка входа по ключу

1. Отключитесь от сервера (`exit`).
2. Попробуйте подключиться снова:

   - **macOS / Linux:**

     ```bash
     ssh -i ~/.ssh/id_ed25519 root@IP_АДРЕС
     ```

   - **Windows (PuTTY):**
     - В PuTTY в разделе **Connection → SSH → Auth** укажите путь к приватному ключу.
     - Подключитесь к серверу.

Если вход прошёл без пароля — всё работает.

#### Отключение входа по паролю

Только после того, как вы убедились, что вход по ключу работает, отключите вход по паролю.

1. Подключитесь к серверу (уже по ключу).
2. Откройте конфиг SSH:

   ```bash
   nano /etc/ssh/sshd_config
   ```

3. Найдите и измените (или добавьте) строки:

   ```text
   PasswordAuthentication no
   ChallengeResponseAuthentication no
   UsePAM no
   ```

4. Сохраните файл и выйдите.
5. Перезапустите SSH:

   ```bash
   systemctl restart sshd
   ```

> [!WARNING]
> **Не отключайте вход по паролю, пока не проверите, что вход по ключу работает.**  
> Иначе вы можете потерять доступ к серверу.

### 2. Смена SSH-порта (опционально)

По умолчанию SSH слушает порт 22. Его часто сканируют боты для брутфорса. Смена порта не даёт 100% защиты, но снижает количество попыток взлома.

#### Как сменить SSH-порт

1. Подключитесь к серверу по SSH.
2. Откройте конфиг:

   ```bash
   nano /etc/ssh/sshd_config
   ```

3. Найдите строку:

   ```text
   #Port 22
   ```

4. Замените на:

   ```text
   Port 2222
   ```

   (можете выбрать другой свободный порт, например 2222, 2200, 2244 и т.д.)

5. Сохраните файл и выйдите.
6. Перезапустите SSH:

   ```bash
   systemctl restart sshd
   ```

7. Проверьте, что порт открыт в фаерволе (об этом ниже).

#### Подключение после смены порта

Теперь при подключении нужно указывать новый порт:

- **macOS / Linux:**

  ```bash
  ssh -p 2222 -i ~/.ssh/id_ed25519 root@IP_АДРЕС
  ```

- **Windows (PuTTY):**
  - В поле «Port» укажите новый порт (например, 2222).

> [!NOTE]
> Смена порта — опциональная мера. Если вам неудобно, можно оставить 22, но тогда особенно важно использовать SSH-ключи и fail2ban.

### 3. Настройка фаервола (UFW)

Фаервол контролирует, какие порты открыты для интернета, а какие закрыты.

#### Установка UFW

На Ubuntu UFW обычно уже установлен. Проверьте:

```bash
ufw version
```

Если нет — установите:

```bash
apt install -y ufw
```

#### Базовая настройка UFW

1. Разрешите SSH (важно сделать это **до** включения фаервола):

   - Если используете стандартный порт 22:

     ```bash
     ufw allow 22/tcp
     ```

   - Если сменили порт (например, 2222):

     ```bash
     ufw allow 2222/tcp
     ```

2. Разрешите порты для панели и VPN:

   - Для Marzban (панель через Caddy, HTTPS):

     ```bash
     ufw allow 443/tcp
     ```

   - Для inbound (например, порт 443 или другой, который вы использовали):

     ```bash
     ufw allow 443/tcp
     ufw allow 8443/tcp
     ```

   (укажите те порты, которые реально используете)

3. Включите фаервол:

   ```bash
   ufw --force enable
   ```

4. Проверьте статус:

   ```bash
   ufw status verbose
   ```

Вы должны увидеть список разрешённых портов.

> [!WARNING]
> **Всегда сначала разрешайте SSH-порт в UFW, и только потом включайте фаервол.**  
> Иначе вы можете заблокировать себе доступ к серверу.

#### Запрет лишних портов

По умолчанию UFW запрещает все входящие соединения, для которых нет правила `allow`. Это правильно. Не открывайте порты «на всякий случай».

### 4. Защита от брутфорса (Fail2ban)

Fail2ban следит за логами и автоматически банит IP, которые слишком часто пытаются подключиться по SSH с неверными данными.

#### Установка Fail2ban

1. Установите пакет:

   ```bash
   apt update
   apt install -y fail2ban
   ```

2. Проверьте статус:

   ```bash
   systemctl status fail2ban
   ```

   Должно быть `active (running)`.

#### Базовая настройка Fail2ban

1. Создайте локальный конфиг:

   ```bash
   cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
   ```

2. Откройте его:

   ```bash
   nano /etc/fail2ban/jail.local
   ```

3. Найдите секцию `[sshd]` и убедитесь, что она включена:

   ```text
   [sshd]
   enabled = true
   ```

4. При желании можно настроить параметры, например:

   ```text
   maxretry = 3
   bantime = 3600
   findtime = 600
   ```

   Это значит:
   - 3 неудачные попытки за 10 минут → бан на 1 час.

5. Сохраните файл и выйдите.
6. Перезапустите Fail2ban:

   ```bash
   systemctl restart fail2ban
   ```

#### Проверка работы Fail2ban

Посмотрите статус:

```bash
fail2ban-client status sshd
```

Вы увидите, сколько IP сейчас забанено.

### 5. Базовые рекомендации по обслуживанию

Несколько простых правил, которые сильно повысят безопасность:

1. **Регулярно обновляйте систему:**

   ```bash
   apt update && apt upgrade -y
   ```

   Делайте это хотя бы раз в 1–2 недели.

2. **Не устанавливайте лишнее.**  
   Чем меньше программ на сервере, тем меньше потенциальных уязвимостей.

3. **Следите за логами.**  
   Хотя бы изредка смотрите:

   ```bash
   journalctl -u sshd --no-pager -n 50
   fail2ban-client status
   ufw status verbose
   ```

4. **Используйте сложные пароли** там, где они ещё есть (панель, почта, домен).

5. **Делайте бэкапы** важных конфигов и данных (об этом будет отдельный раздел).

### 6. Что дальше

После настройки безопасности можно спокойно переходить к:

- установке и настройке панелей (Marzban / Remnawave);
- созданию inbound'ов и пользователей;
- подключению клиентов.

Безопасность — это не разовое действие, а процесс. Но даже описанных выше мер достаточно, чтобы ваш сервер был защищён намного лучше, чем «из коробки».

## 🛡️ Безопасность сервера (Защита от атак и брутфорса)

Как только ваш VPS активируется, хакерские боты начинают круглосуточно сканировать его порты и пытаться подобрать пароль к SSH. Чтобы ваш VPN-сервер не взломали и не заблокировали за спам, мы с вами обязательно настроим защиту нашего сервера.

> [!IMPORTANT]
> Выполняйте шаги строго по порядку. Не закрывайте текущую сессию терминала, пока полностью не убедитесь, что всё настроено верно, иначе вы можете заблокировать доступ к собственному серверу!

---

### Выберите способ настройки порта SSH:

<details>
<summary><b>🟢 ВАРИАНТ 1: Легкий способ в одну команду (Для новичков)</b></summary>
<br>

Если вы боитесь вручную редактировать системные файлы через `nano`, используйте эту автоматическую команду. Она сама сделает всё за вас без риска стереть что-то лишнее.

1. Запустите автоматический скрипт конфигурации SSH:
   ```bash
   sudo apt install sed -y && sudo sed -i 's/#Port 22/Port 2222/g' /etc/ssh/sshd_config && sudo sed -i 's/Port 22/Port 2222/g' /etc/ssh/sshd_config
   ```
   *(Эта команда сама найдет нужную строчку в системе и безопасно заменит стандартный порт 22 на новый порт `2222`)*.

2. **Обязательно** откройте этот порт в брандмауэре UFW, чтобы сервер вас не заблокировал:
   ```bash
   sudo ufw allow 2222/tcp
   ```

3. Перезапустите службу SSH, чтобы изменения вступили в силу:
   ```bash
   sudo systemctl restart ssh
   ```

</details>

<details>
<summary><b>🔥 ВАРИАНТ 2: Продвинутый способ вручную (Для профи + Вход по ключам)</b></summary>
<br>

Классический проверенный метод с полным отключением паролей и переходом на криптографические ключи.

#### Шаг 1. Перенос SSH на нестандартный порт вручную
1. Откройте конфигурационный файл SSH:
   ```bash
   sudo nano /etc/ssh/sshd_config
   ```
2. Найдите строку `#Port 22` (или `Port 22`).
3. Раскомментируйте её (уберите знак `#`, если он есть) и измените номер порта:
   ```text
   Port 2222
   ```
4. Сохраните файл (`Ctrl+O`, затем `Enter`) и выйдете (`Ctrl+X`).
5. **Если вы используете брандмауэр UFW, обязательно разрешите новый порт перед перезапуском!**
   ```bash
   sudo ufw allow 2222/tcp
   ```
6. Перезапустите службу SSH, чтобы применить настройки:
   ```bash
   sudo systemctl restart ssh
   ```
*Теперь при новом подключении к серверу вам нужно будет указывать порт 2222 (в Termius или через команду `ssh root@IP -p 2222`).*

#### Шаг 2. Вход по SSH-ключам (Отключение паролей)
Подбор текстового пароля — это вопрос времени. Авторизация по SSH-ключам использует асимметричное шифрование: войти на сервер сможет только тот компьютер, на котором физически лежит ваш приватный ключ. При этом вход по обычным паролям полностью блокируется.

1. **На своем домашнем компьютере** (в терминале Linux/Mac или PowerShell в Windows) сгенерируйте пару ключей:
   ```bash
   ssh-keygen -t ed25519 -C "my-vps-key"
   ```
   *(Нажимайте Enter, чтобы сохранить настройки по умолчанию)*.
2. Скопируйте ваш публичный ключ на VPS-сервер:
   ```bash
   ssh-copy-id -p 2222 root@IP_ВАШЕГО_СЕРВЕРА
   ```
3. Проверьте, что теперь вы можете зайти на сервер без ввода пароля.
4. **Полностью отключите вход по паролям.** На сервере снова откройте файл `/etc/ssh/sshd_config`, найдите и измените следующие параметры:
   ```text
   PasswordAuthentication no
   PermitRootLogin prohibit-password
   ```
5. Перезапустите SSH: `sudo systemctl restart ssh`. Теперь боты физически не смогут перебирать пароли.

</details>

### Шаг 3. Установка Fail2Ban (Автобан для хакеров)
*Этот шаг обязателен для обоих вариантов.* 

**Fail2Ban** сканирует системные логи и, если видит, что кто-то несколько раз подряд неправильно ввел пароль или пытается взломать вашу панель `3x-ui`, он автоматически блокирует IP-адрес этого атакующего на уровне системы.

1. Установите утилиту одной командой:
   ```bash
   sudo apt update && sudo apt install fail2ban -y
   ```
2. Запустите и включите автозапуск при старте сервера:
   ```bash
   sudo systemctl start fail2ban
   sudo systemctl enable fail2ban
   ```
3. Базовые настройки уже защищают SSH. Чтобы проверить статус работы и список забаненных ботов, используйте команду:
   ```bash
   sudo fail2ban-client status sshd
   ```
### 🏁 Заключение по безопасности

Выполнение этих простых шагов поднимает защиту вашего VPS на уровень корпоративных стандартов:
* **Смена порта** убирает ваш сервер с радаров 99% автоматических хакерских ботов.
* **Отключение паролей** делает ручной подбор (брутфорс) технически невозможным.
* **Fail2Ban** выступает в роли умного щита, который мгновенно изолирует любых подозрительных «гостей».

Теперь ваш VPN-сервер не просто обходит ограничения, но и надежно защищен от взлома. Можно спать спокойно! 🛡️
